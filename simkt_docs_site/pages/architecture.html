Arquitetura

O SimKT é organizado em três camadas independentes coordenadas pelo Environment. Entender essa estrutura facilita estender a biblioteca e depurar simulações complexas.

Visão geral em três camadas

⚙️

Camada 1 — Scheduler

SimClock, SimScheduler, SimEvent. Mantém a fila de prioridade e avança o relógio evento a evento.

🔄

Camada 2 — Processos

SimProcess, SimProcessContext. Usa coroutines Kotlin de baixo nível para suspender e retomar processos via hold() e await().

📦

Camada 3 — Primitivos

SimResource, SimChannel, SimQueue, SimContainer, SimContinuousModel. Cada primitivo cria e agenda eventos internamente.

O papel do Environment

Environment é a fachada que conecta as três camadas. Ele não executa lógica de negócio — apenas expõe os pontos de entrada: criar primitivos, registrar processos e disparar o loop de eventos. 

// Environment coordena tudo
val env = Environment()

// Camada 3 — primitivo criado pelo Environment
val recurso = env.resource("antena", capacity = 1)

// Camada 2 — processo registrado no Environment
env.process(SimProcess { ctx ->
    val token = ctx.request(recurso)  // bloqueia se recurso ocupado
    ctx.hold(2.0)
    ctx.release(recurso, token)
})

// Camada 1 — scheduler roda o loop
env.run(until = SimTime(10.0))

Como os processos funcionam

SimKT não usa kotlinx.coroutines. Em vez disso, usa a API de coroutines de baixo nível do Kotlin: startCoroutine e suspendCoroutine.

Quando um processo chama ctx.hold(5.0), o que acontece é:

  1. Um SimEvent é criado com time = now + 5.0.
  2. O evento é adicionado à fila do scheduler.
  3. A coroutine é suspensa — ela salva seu estado (ponto de execução, variáveis locais) em um objeto Continuation.
  4. O Continuation fica armazenado dentro do SimEvent.
  5. O scheduler avança para o próximo evento. Quando chega ao evento agendado, chama event.trigger(), que chama continuation.resume().
  6. O processo retoma exatamente de onde parou.
Isso significa que nenhuma thread é bloqueada. Centenas de processos podem estar "esperando" simultaneamente com zero overhead de thread.

Ciclo de vida de um evento

Todo SimEvent passa por estados bem definidos: 

// PENDING → TRIGGERED (execução normal)
event.trigger()     // ou triggerWith(value)

// PENDING → CANCELLED (cancelamento explícito)
event.cancel()

// Consulta de estado
event.isPending
event.isTriggered
event.isCancelled
Um evento cancelado é ignorado pelo scheduler. Recursos e canais usam cancelamento internamente para limpar filas de espera.

Relação entre os componentes

Environment
├── SimClock        — mantém env.now (SimTime)
├── SimScheduler    — fila de prioridade (time, sequence)
├── SimMonitor      — log de eventos (env.monitor)
├── SimRandomProvider — RNG com seed (env.random)
│
├── process()       ── registra SimProcess
│   └── SimProcessContext — hold / await / request / release / ...
│
├── resource()      ── cria SimResource
├── channel()       ── cria SimChannel
├── store()         ── cria SimQueue
├── container()     ── cria SimContainer
└── continuous()    ── cria SimContinuousRunner (SimProcess interno)

Simulation — fachada opcional

Simulation é uma camada fina sobre Environment que adiciona um nome, uma lista de SimEntity e o método printReport(). Ela não altera o comportamento do motor — apenas organiza a simulação como um objeto nomeado. 

val sim = Simulation("Missão Alpha")
// sim.env é o Environment subjacente — todas as APIs funcionam igual
sim.addProcess(SimProcess { ctx -> ctx.hold(5.0) })
sim.run(until = 60.0)
sim.printReport()
