SimContinuousModel

fun interface SimContinuousModel { fun step(context: SimProcessContext, deltaTime: Double) }

SimContinuousModel permite integrar dinâmicas de passo fixo (movimento, consumo de bateria, sensores com ruído) dentro do loop de eventos discretos. A cada stepSize unidades de tempo, todos os modelos registrados são chamados com o deltaTime correspondente.

Por que é útil? Simulações reais frequentemente misturam eventos discretos ("radar detectou alvo") com dinâmicas contínuas ("posição do drone muda a 2 m/s"). SimContinuousModel une os dois mundos sem precisar de outro framework.

Como usar

Registre um ou mais modelos com env.continuous():

env.continuous(
    stepSize = 1.0,           // executa a cada 1 unidade de tempo
    until    = SimTime(10.0), // para em t=10 (opcional)
    models   = arrayOf(meuModelo)
)

Internamente, env.continuous() cria um SimProcess que chama model.step(ctx, stepSize) a cada passo e depois faz ctx.hold(stepSize). Ele coexiste com todos os outros processos no mesmo scheduler.

Assinatura do step

ParâmetroTipoDescrição
contextSimProcessContextContexto do processo interno. Dá acesso a ctx.env, ctx.now e todos os métodos suspensos.
deltaTimeDoubleTamanho do passo — sempre igual ao stepSize configurado em env.continuous().

Exemplo: movimento linear

val env = Environment()
var posicao = 0.0
val velocidade = 2.0  // unidades por tempo

env.continuous(
    stepSize = 1.0,
    until    = SimTime(5.0),
    SimContinuousModel { ctx, dt ->
        posicao += velocidade * dt
        ctx.env.monitor.record(ctx.now, "posição: $posicao")
    }
)

env.run(until = SimTime(10.0))
env.monitor.printAll()

Saída esperada

[SimTime(value=1.0)]: posição: 2.0 [SimTime(value=2.0)]: posição: 4.0 [SimTime(value=3.0)]: posição: 6.0 [SimTime(value=4.0)]: posição: 8.0 [SimTime(value=5.0)]: posição: 10.0

Exemplo: dreno de bateria com modo econômico

val env = Environment()
val bateria = env.container("bateria", capacity = 100.0, initialLevel = 100.0)
var modoEconomico = false

// Modelo contínuo: drena a bateria a cada passo
val drainModel = SimContinuousModel { ctx, dt ->
    val taxa = if (modoEconomico) 1.0 else 3.0
    val drain = minOf(taxa * dt, bateria.level)
    if (drain > 0.0) bateria.get(drain)

    if (bateria.level <= 0.0) ctx.env.stop()
}

// Processo discreto: ativa modo econômico quando bateria < 30%
val sensorProcess = SimProcess { ctx ->
    while (bateria.level > 0.0) {
        ctx.hold(5.0)
        val pct = bateria.level
        ctx.env.monitor.record(ctx.now, "bateria: ${"%.1f".format(pct)}%")

        if (!modoEconomico && pct < 30.0) {
            modoEconomico = true
            ctx.env.monitor.record(ctx.now, "MODO ECONÔMICO ATIVADO")
        }
    }
}

env.continuous(stepSize = 1.0, models = arrayOf(drainModel))
env.process(sensorProcess)
env.run(until = SimTime(100.0))
env.monitor.printAll()

Múltiplos modelos

val posModel = SimContinuousModel { ctx, dt ->
    posicao += velocidade * dt
}

val rumorModel = SimContinuousModel { ctx, dt ->
    // adiciona ruído gaussiano simples
    ruido = ctx.env.random.nextDouble(-0.5, 0.5) * dt
}

// Ambos são chamados a cada passo na ordem em que foram passados
env.continuous(stepSize = 0.1, SimContinuousModel { ctx, dt ->
    // ...
}, SimContinuousModel { ctx, dt ->
    // ...
})
Não use ctx.hold() dentro de step(). O hold já é feito automaticamente pelo SimContinuousRunner entre cada passo. Chamar hold dentro do step causa comportamento inesperado.
