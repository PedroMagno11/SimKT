FAQ

Perguntas frequentes sobre o SimKT.

Qual versão do Kotlin é necessária?

Kotlin 2.3.20 ou superior, compilando para JVM 1.8 (Java 8) ou mais recente. Verifique o pom.xml do projeto para os valores exatos.

O SimKT usa kotlinx.coroutines?

Não. O SimKT usa a API de coroutines de baixo nível do Kotlin (startCoroutine, suspendCoroutine, Continuation). Esses tipos fazem parte da stdlib do Kotlin — sem dependências externas. Você não precisa adicionar kotlinx.coroutines ao seu projeto.

O que "experimental" significa para a API?

Significa que a API pode mudar entre versões menores sem aviso prévio. Campos, nomes de classes e comportamentos podem ser renomeados ou removidos. Não use o SimKT em produção em sistemas críticos — ele é destinado a estudo, prototipação e experimentação.

hold(5.0) significa 5 segundos?

Não. O SimKT usa tempo adimensional. A unidade é o que você decidir: segundos, minutos, ticks, ciclos. Se você define que 1 unidade = 1 segundo, então hold(5.0) é 5 segundos. A biblioteca não impõe interpretação.

O SimKT é thread-safe?

Não. O SimKT é single-threaded por design. Toda a simulação roda em uma única thread. Isso é intencional — garante determinismo e elimina race conditions. Não compartilhe um Environment entre threads.

Qual a diferença entre SimChannel e SimTopic?

SimChannelSimTopic
Integração com tempoSim — send/receive participam do schedulerNão — entrega síncrona imediata
Múltiplos receiversNão (um por vez)Sim (N ouvintes por nome)
BackpressureSim (buffer limitado)Não
SuspensãoSim (ctx.send/receive)Não (síncrono)

Use SimChannel para pipelines de dados entre processos. Use SimTopic para notificações broadcast sem integração com o tempo.

Como garantir resultados reproduzíveis?

Use SimConfig(randomSeed = N):

env.run(SimConfig(until = SimTime(100.0), randomSeed = 42L))

Com a mesma seed e o mesmo código, toda execução produz exatamente o mesmo resultado.

Como parar a simulação de dentro de um processo?

env.process(SimProcess { ctx ->
    while (true) {
        ctx.hold(1.0)
        if (condicaoDeParada) ctx.env.stop()  // para no próximo ciclo
    }
})

O que acontece quando env.run() termina sem atingir o limite?

Se a fila de eventos se esgotar antes de until ser atingido, env.run() retorna normalmente. Isso acontece quando todos os processos terminam sem agendar novos eventos. É o comportamento esperado para simulações finitas.

Posso rodar múltiplos cenários com o mesmo Environment?

Sim, use env.reset() entre os cenários:

// Cenário 1
env.process(...)
env.run(until = SimTime(100.0))
env.monitor.printAll()

// Limpa tudo: relógio, fila, monitor, contador de processos
env.reset()

// Cenário 2
env.process(...)
env.run(until = SimTime(100.0))
env.monitor.printAll()
